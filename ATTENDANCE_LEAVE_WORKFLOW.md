# Attendance & Leave Modules Documentation

This document describes the workflow, data design, and user interactions for the Attendance Tracking and Leave Management modules in the School Management SaaS.

---

## 1. Attendance Module Workflow

The Attendance module tracks student presence on a daily, session-based (Forenoon/Afternoon) level. 

### Roles involved:
- **Teacher:** Marks, edits, and exports attendance for their assigned class.
- **Admin:** Views and overrides attendance for any class across the school.
- **Parent:** Views historical attendance logs and real-time statistics for their child.

```text
[Teacher selects Date & Session]
         ↓
[List of students in Class fetched]
         ↓
[Daily attendance defaults to 'Present']
         ↓
[Teacher toggles student statuses: Present / Absent / Late]
         ↓
[Save Attendance writes to Firestore]
```

### Detailed Steps:
1. **Selection:** The teacher selects a Date (defaults to today) and a Session (`FN` for Forenoon, `AN` for Afternoon).
2. **Retrieve Students:** The application queries all active student profiles under the teacher's assigned class (`assignedClassId`).
3. **Optimistic Loading:** If a record already exists in Firestore for that date & session, it loads the saved state. If not, it defaults every student to `Present` for faster marking.
4. **Marking:** The teacher marks students who are `Absent` or `Late`.
5. **Persistence:** Clicking "Save Attendance" executes `saveAttendance()` in `firestore.js`, saving the record under `schools/{schoolId}/attendance/{classId}_{dateString}`.
6. **Reporting & Exports:** Teachers and Admins can switch view modes to "Reports" (Weekly, Monthly, or Term-wise aggregates) and export the columns dynamically to an Excel spreadsheet using `xlsx`.

## 2. Leave Management Module Workflow

Teachers and Students (via Parents) can request leaves, which are processed by School Admins.

### Roles involved:
- **Applicant (Teacher / Parent on behalf of Student):** Submits leave requests with optional attachments.
- **Approver (Admin / Accountant):** Evaluates, approves, or rejects requests.

```text
[Applicant fills Leave Form] ──> [Uploads Supporting Document]
                                                ↓
[Submits request to schools/{id}/leaves (Status: Pending)]
                                                ↓
[Admin reviews application in Leave Management Dashboard]
                                                ↓
[Admin marks request as 'Approved' or 'Rejected']
                                                ↓
[Applicant sees updated status real-time on portal]
```

### Detailed Steps:
1. **Creation:** An applicant opens the "Request Leave" modal, selecting the leave type (`Annual`, `Sick`, `Maternity`, `Paternity`, or `Others`), start date, end date, and reason.
2. **Document Upload:** If selected, a supporting document (PDF/Image) can be attached (handled with client-size validation).
3. **Submission:** The leave document is written to `schools/{schoolId}/leaves` with status set to `Pending` and a `submittedAt` ISO timestamp.
4. **Admin Review:** Admins are notified of pending leaves. They can read details, view attached documents, and click **Approve** or **Reject**.
5. **Real-time Sync:** An active Firestore listener (`onSnapshot`) ensures the applicant’s leave logs update instantly without reloading the page.

## 3. Database Design

### Subcollection: `schools/{schoolId}/attendance`
Stores the daily marked records per class and date session.
- **Document ID Format:** `{classId}_{dateString}` (e.g., `grade5_2026-07-28_FN`)
- **Fields:**
  - `classId` (String)
  - `date` (String - format `YYYY-MM-DD` or `YYYY-MM-DD_FN`)
  - `markedBy` (String - UID of teacher/admin who marked it)
  - `records` (Map - `{ studentId: "Present" | "Absent" | "Late" }`)
  - `updatedAt` (Timestamp)

### Subcollection: `schools/{schoolId}/leaves`
Stores all employee (teacher) and student leave applications.
- **Document ID Format:** Auto-generated by Firestore
- **Fields:**
  - `applicantId` (String - UID of applicant)
  - `applicantName` (String)
  - `applicantRole` (String - `'teacher'` or `'parent'`)
  - `leaveType` (String)
  - `startDate` (String - `YYYY-MM-DD`)
  - `endDate` (String - `YYYY-MM-DD`)
  - `reason` (String)
  - `status` (String - Enum: `'Pending'` | `'Approved'` | `'Rejected'`)
  - `submittedAt` (Timestamp - ISO String)
  - `supportingDoc` (Map - `{ name, size, url }`)

## 4. Firestore Security Rules

The security rules enforce access boundaries as follows:

```javascript
// Attendance Rules
match /attendance/{document=**} { 
  allow read: if belongsToSchool(schoolId); 
  allow write: if isAdminOfSchool(schoolId) || isTeacherOfSchool(schoolId); 
}

// Leave Requests Rules
match /leaves/{document=**} {
  allow read: if belongsToSchool(schoolId);
  allow write: if isAdminOfSchool(schoolId) || isTeacherOfSchool(schoolId) || isParentOfSchool(schoolId);
}
```

## 5. UI Features & UX Design

- **Status Badges:** Dynamic colors distinguish leave states:
  - **Pending:** Amber badge with a pulsing micro-animation.
  - **Approved:** Solid emerald green badge.
  - **Rejected:** Solid red badge.
- **Filters:** Leave Management has tabs to split **Pending Requests** and **History** to keep the workspace clean.
- **Export Control:** The Attendance page contains a modular column selector modal, enabling users to choose exactly which fields to include in the generated Excel report.
- **Responsive Layouts:** Tables adapt into card layouts on mobile screens to prevent text overlap.
